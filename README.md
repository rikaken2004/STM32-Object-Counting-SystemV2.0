# 51双机计数控制系统

## 项目简介

两个51单片机通过串口通信，一个管人机交互（按键、数码管显示、红外计数），一个管电机控制，拼成一个能设置目标次数、自动计数、到数停机的控制系统。

## 硬件连接

### 主单片机（负责交互和计数）

| 引脚 | 接了什么 | 干嘛的 |
|------|----------|--------|
| P3^2 | 加值键（KEY_ADD） | 设置模式下按一次，目标值+1（0-99循环） |
| P3^3 | 确认键（KEY_CONFIRM） | 双重功能：①设置模式确认目标值启动计数 ②任何时候按一次清零重启 |
| P3^4 | 红外传感器（IR_SENSOR） | 物体穿过触发计数 |
| P3^6 | 红外触发LED（LED_IR） | 每次红外检测到物体时闪一下 |
| P3^7 | 完成LED（LED_FINISH） | 计数达到目标值时亮起 |
| P0^0,P2.0-2.3，P2.7-2.4, | P1.0-1.3,P0.2-P0.3,P1.4-1.7|两位数码管位选（目标值/计数值） | 分别显示预置数和实时计数值 |
| P0^5~P0^7,P2.0-2.7 | 四位数码管位选（累计总值） | 显示累计完成的次数（最多9999） |
| P2口 | 数码管段码输出（8位） | 所有数码管共用段码线 |
| P1口 | 第二个两位数码管段码 | 计数值的数码管独立段码 |

我当初设计引脚的时候，把P0口拆成8个独立的位选线，每个数码管单独控制，这样动态扫描的时候可以精确控制每一位的亮灭时间。代价就是占用了整个P0口。还有两个数码管复用接口的方案。

### 副单片机（负责电机控制）

| 引脚 | 接了什么 | 干嘛的 |
|------|----------|--------|
| P2^0 | L298N使能A（ENA） | 控制电机A的使能 |
| P2^2 | L298N使能B（ENB） | 控制电机B的使能 |
| P2^6 | L298N IN1 | 电机A方向控制1 |
| P2^3 | L298N IN2 | 电机A方向控制2 |
| P2^3 | L298N IN3 | 电机B方向控制1 |
| P2^4 | L298N IN4 | 电机B方向控制2 |
| P1^0 | 调试LED（LED_DEBUG） | 电机停止时亮起，方便调试 |
| P3^0/RxD | 串口接收 | 接收主单片机指令 |
| P3^1/TxD | 串口发送 | 发送回传指令 |

### 双机通信

```
主单片机 TxD(P3^1) → 副单片机 RxD(P3^0)
主单片机 RxD(P3^0) ← 副单片机 TxD(P3^1)
GND → GND（共地是必须的，不然串口电平没有一个基准）
```

指令定义：
- `0x01`：启动电机
- `0x02`：停止电机

## 软件架构

### 主单片机（主机）

```
main()
├── 初始化：串口、变量清零、LED熄灭
└── while(1) 主循环
    ├── seg_display()        // 数码管动态扫描（优先执行，防止闪烁）
    ├── key_process()        // 按键处理
    │   ├── 加值键：目标值+1（仅设置模式有效）
    │   └── 确认键：确认目标值 或 清零重启
    └── ir_count_process()   // 红外计数处理
        └── 达到目标值时发送停止指令给副机
```

我当时把`seg_display()`放在主循环最前面，是因为数码管动态扫描必须频繁调用才能保持亮度。如果按键处理或红外检测占了太多时间，数码管就会暗下来。这个顺序是我试了好几次才定下来的。

### 副单片机（从机）

```
main()
├── 初始化：串口、电机默认启动
└── while(1) 主循环
    └── Motor_Stop_Restart()  // 电机启停逻辑
        ├── 收到停止指令 → 停5秒
        ├── 发送回传指令(0x02)给主机
        └── 5秒后自动重启
```

副单片机其实很"傻"，它只在主循环里反复检查`stop_flag`。如果标志被置位就停5秒然后重启。停止指令是通过串口中断写入的。

### 串口中断

```
主单片机：UART_ISR()
└── 收到0x02 → recv_flag=1 → 累计值+1，重置计数状态

副单片机：UART_ISR()
├── 收到0x01 → stop_flag=1 → 电机停止
├── 收到0x02 → 无操作（保留）
└── 指令多数表决：3次接收取多数，防干扰
```

### 指令可靠性设计

主单片机每次发送指令时，**连续发送2次**，间隔5ms。副单片机用**3字节缓存做多数表决**，3次接收里出现至少2次相同值才算有效指令。

这个设计的来源是：一开始我只发一次，结果副单片机偶尔收不到，电机该停不停。后来改成发两次+多数表决，问题基本解决了。虽然不优雅，但管用。

### 副单片机自动重启机制

```
if(stop_flag) {
    delay_restart++;
    if(delay_restart >= 300) {  // 300×10ms=3秒
        motor_control(1);       // 自动重启电机
    }
}
```

停机后大约3秒自动重启电机。这个机制是客户需求——停一段时间后要自动恢复运行，不需要人工干预。

## 关键技术决策

### 为什么用两个单片机，不用一个？

一开始我尝试用一个单片机同时管数码管、按键、红外计数、电机控制和串口通信。结果数码管动态扫描一跑，电机那边的定时就不准了；电机一转，数码管就灭。

后来想通了：**显示交互和电机控制是两件性质完全不同的事**。显示交互需要频繁轮询（毫秒级），电机控制需要持续输出（秒级）。硬塞在一起，两边都做不好。

两个单片机串口通信，各干各的，问题就简单了。

### 为什么用L298N而不是TB6612？

TB6612模块我也有，但L298N更皮实。L298N是双H桥驱动，能同时控制两个电机，而且耐压范围宽（最高46V），我这个项目只需要驱动两个小直流电机，L298N完全够用。

缺点就是L298N体积大、效率低（线性驱动，发热大）。但小项目无所谓，不用追求那点效率。

### 为什么串口指令发两次？

刚联机测试的时候，副单片机偶尔收不到停止指令。排查了一下，发现是串口中断在处理其他任务的时候错过了起始位。

解决方案很粗暴：**发两次**。第一次丢失了还有第二次。副单片机那边用3次接收的多数表决来判断，能滤掉单次误码。

严格来说这不是一个规范的做法，但在这个简单的控制场景里够用了。

### 清零键的设计思路

确认键（KEY_CONFIRM）有两个功能：
1. **设置模式下（目标值>0）**：确认目标值，启动计数
2. **任何时候按**：清零重启（目标值、计数值、状态全部复位）

这是我想出来的需求——他们想要一个"一键回到初始状态"的按钮，不管系统在什么状态，按一下就能重新开始。设计的时候我犹豫过要不要区分短按长按，后来发现没必要——按一下直接恢复到初始状态，简单明确，不会让用户困惑。

## 踩坑记录

### 坑1：数码管闪烁，特别是运行几个回合后必然熄灭

**现象**：系统刚上电的时候数码管显示正常，跑完一个回合（红外触发→计数→达到目标→电机停）之后，数码管亮度明显变暗，再多跑几轮就彻底灭了。

**排查过程**：
1. 我一开始以为是电源问题，用万用表量5V电压，稳定
2. 换了一个新的数码管，故障依旧
3. 拔掉电机驱动模块的电源，只留单片机跑，数码管不灭了
4. 怀疑是电机启动时瞬时电流大，拉低了电源电压
5. 在电机电源和单片机电源之间加了100μF电解电容，情况好转但没根除
6. 后来在主循环里加了调试LED闪烁，发现电机停转之后，主循环的执行速度变慢了
7. 数了一下代码，`seg_display()`函数在红外处理时被阻塞了——红外检测里有`while(IR_SENSOR == 0)`等待释放的循环，这个循环里虽然调了`seg_display()`，但循环次数太多（传感器释放需要几百毫秒），导致数码管扫描频率严重下降

**解决方案**：
1. 把红外检测的等待释放循环删除，改为用标志位做状态机
2. `seg_display()`放到主循环最前面，确保每次循环都先执行显示
3. 在`key_process()`和`ir_count_process()`的等待释放循环里也加上`seg_display()`调用
4. 最终效果：数码管稳定显示，不再熄灭

**后来想明白**：数码管动态扫描必须保证一定的刷新率（至少50Hz），而阻塞操作会把刷新时间占掉。肉眼看到的就是"灭了"。

### 坑2：副单片机停不了机

**现象**：主单片机计数达到了目标值，发送了停止指令（0x02），副单片机继续转，LED_FINISH亮了，电机还在嗡嗡响。

**排查过程**：
1. 主单片机串口调试LED（LED_UART）从不亮 → 怀疑主单片机根本没发指令
2. 用示波器量主单片机TxD引脚，按下确认键时有信号输出
3. 再量副单片机RxD引脚，信号幅度只有2V左右，不是标准TTL电平
4. 恍然大悟：**两根单片机之间的串口线太长（约30cm），信号衰减了**
5. 试着缩短连接线到10cm，信号恢复到接近5V，但偶尔还是会丢包

**解决方案**：
1. 主单片机发送指令时连续发2次，间隔5ms
2. 副单片机用3次接收的多数表决来确认指令（缓存3个接收值，取多数）
3. 同时降低波特率到2400bps试过，但后来9600bps+重发方案更可靠
4. 最终放弃缩短线长，用软件方案解决

### 坑3：串口中断和主循环抢资源，导致显示卡顿

**现象**：串口通信频繁的时候，数码管闪烁更加严重。特别是副单片机回传0x02时，数码管会暗一下。

**排查过程**：
1. 串口中断里只做了最少的操作（读SBUF、置标志位），应该不会占太多时间
2. 用示波器量了一下中断响应时间：从触发到退出大约20μs，不算长
3. 但问题在于**主循环里`while(IR_SENSOR == 0) seg_display()`这个循环**——如果传感器被长时间遮挡，主循环卡在这里，中断虽然能响应，但`seg_display()`只在这个过程中被调用，频率不够
4. 串口中断退出后，继续执行`while(IR_SENSOR == 0)`的循环，主循环推进不了，数码管自然就暗了

**解决方案**：
1. 把`while`等待传感器释放的阻塞结构改为**状态机**——用标志位记录"正在等待释放"，在主循环里轮询传感器状态
2. 如果传感器还没释放，就只是不增加计数，主循环照常跑`seg_display()`
3. 这样串口中断和数码管扫描互不影响

**代码改动示例**（原来）：
```c
while(IR_SENSOR == 0) seg_display();
```

**改成**：
```c
if(wait_release) {
    if(IR_SENSOR == 1) wait_release = 0;
} else {
    // 正常检测
}
```

### 坑4：确认键功能逻辑混乱

**现象**：确认键有时候是"确认目标值"，有时候是"清零重启"，搞不清楚当前在哪个状态。

**排查过程**：
1. 代码里确实有两个功能，但区分条件不够清晰
2. 原来我判断的是`if(KEY_CONFIRM == 0 && target_val > 0)`作为确认条件，但如果用户目标值设为0，就永远进不了确认逻辑

**解决方案**：
1. 区分条件改为`if(KEY_CONFIRM == 0 && set_state == 1 && target_val > 0)`——明确要求当前必须是设置状态且目标值不为0
2. 其他情况（包括设置状态但目标值为0、计数中、计数完成）一律走清零重启
3. 用`set_state`变量明确标记当前模式，用户操作前看一眼数码管1（显示预置数）就知道当前能不能修改

**教训**：按键的多功能设计一定要有清晰的逻辑区分，不能让用户"猜"当前按下去是什么效果。

## 演示效果

上电后：
1. 两个数码管都显示"00"，LED全灭
2. 按加值键，数码管1（目标值）从0开始循环增加
3. 设好目标值（比如05），按确认键 → 进入计数模式，红外传感器开始检测
4. 用手或物体遮挡红外对射传感器，数码管2（计数值）+1，同时红外触发LED闪一下
5. 计数值达到目标值（05）时，完成LED亮起，副单片机电机制停止
6. 副单片机停5秒后自动重启电机，同时累计总值+5
7. 按确认键可随时清零，回到初始状态

**正常工作时**：数码管稳定显示，没有闪烁；按键响应灵敏；红外传感器遮挡触发可靠；电机按指令启停。
